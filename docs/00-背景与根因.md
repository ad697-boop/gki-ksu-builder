# 背景与根因

## 设备

- 小米 12（cupid，2201123G），高通 SM8450（Snapdragon 8 Gen1）
- A/B 分区（当前 slot 曾为 a，后为 b），**没有 init_boot 分区**，内核刷在 `boot` 分区
- `fastboot boot` 临时引导在该设备上被忽略，只能 `fastboot flash boot`
- `adb root` 默认禁用（需开发者选项开启才能读 pstore/dmesg）

## 内核真相（核心）

所有类原生 ROM（LineageOS 23.x、LMODroid 6.2、EvolutionX 等）给 cupid 用的都是**高通 OSS 内核**：

- 仓库：`LineageOS/android_kernel_xiaomi_sm8450`
- 分支/版本对照：
  - lineage-22.2 → 5.10.245（LMODroid 6.2）
  - lineage-23.0 / 23.1 → 5.10.247（EvolutionX 2026-02 包）
  - lineage-23.2 → 5.10.256（20260820 nightly）
- 版本号里 `-gki-` 是 `CONFIG_LOCALVERSION="-gki"` 伪装的；`-g<12位sha>` 来自 `CONFIG_LOCALVERSION_AUTO=y`
- 伪装目的：vendor_boot 里 54 个预编译 vendor 模块的 vermagic 必须与内核完全一致（如 `5.10.256-gki-ge682ed2de56f SMP preempt mod_unload modversions aarch64`）

证据链（本机已核对）：

1. ROM boot 内核 vermagic 与 vendor_boot 模块 vermagic 一字不差；
2. `ge682ed2de56f` 就是 LineageOS sm8450 仓库 lineage-23.2 分支 commit `e682ed2de56f...`；
3. 内核配置含 ~900 个高通专属项（`ARCH_WAIPIO/CAPE/DIWALI=y`、QCOM 驱动 `=m`），真 GKI 内核不可能有。

## 为什么其它方案都失败

| 方案 | 结果 | 原因 |
|---|---|---|
| 管理器"修补 boot.img"（LKM） | 不生效（能开机、无 root） | 通用 ksu.ko 过不了 vermagic + modversions CRC |
| 刷官方/ShirkNeko GKI KSU 内核 | 无限重启 | 真 GKI 内核缺高通平台支持、驱动、DTB |
| 自编"同版本号" GKI 内核（android12-5.10 @ g992742f9cdcc） | 无限重启 | 只有版本号一样，内核本体还是 GKI，缺 900 个高通配置 |
| 临时 `fastboot boot` | 被忽略 | 该设备 bootloader 不支持 |
| 换 XDA 预编译 cupid SukiSU 内核 | 版本不匹配 | 那是给 lineage-23.0/23.1（5.10.247）编的，与 23.2（5.10.256）vendor 模块对不上 |

## 正确做法

用 ROM 同源 commit 的内核源码（如 lineage-23.2 @ e682ed2d）+ 同款 clang，把 SukiSU **编译进内核**，并保证：

- 内核版本字符串与原厂**逐字节一致**（vermagic 精确匹配）
- 内核配置与原厂一致（从原厂 boot 内核 IKCONFIG 提取）
- 只替换 boot.img 里的 kernel，ramdisk/header 保持原厂

这样 vendor 模块照常加载，root 生效。
