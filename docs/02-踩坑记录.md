# 踩坑记录（已修复）

## 方向性

1. **GKI 方案全灭**：cupid 内核不是 GKI，自编 GKI 内核刷入无限重启。必须用高通 OSS 内核源码。
2. **管理器 LKM 修补不生效**：通用 ksu.ko 过不了 vermagic + modversions CRC。

## 工具链

3. payload-dumper：用 ssut/payload-dumper-go v2.0.2（tag 无 `v` 前缀；二进制名要 find 动态找）。
4. magiskboot：用官方 Magisk APK 里的 `libmagiskboot.so`（Rust 版 repack 有 ENOENT bug）；
   日志走 stderr，要 `2>&1`；解包后要把 boot.img 复制进工作目录才能 repack。

## 构建

5. **runner OOM**：full LTO 改 thin LTO + 8G swap（先 `swapoff -a` 再重建）。
6. **vermagic 多 `+`（最重要）**：git 树脏时 setlocalversion 输出 `+`，与 vendor 模块不匹配。
   修复：`export LOCALVERSION=""` 抑制；校验改 vermagic 精确相等（不能前缀匹配）。
7. ReKernel-X LKM：官方 ko vermagic 不匹配必须重编；源码放内核树 `drivers/rekernel_x`（相对 include）；
   先 `make modules_prepare` 生成 module.lds，再 `cp vmlinux.symvers Module.symvers`。

## SukiSU / ReSukiSU

8. `KSU_VERSION` 不是由 tag 决定（SukiSU=40000+提交数-2815），要 sed 强制写死（如 40796）；
   ReSukiSU=30000+提交数+700，自动算，不强制。
9. **builtin 最新代码与 v4.1.3 管理器协议不匹配**（app profile v3/v4，报 Unsupported profile version）。
   SUSFS 构建必须 pin `6c13a069`（KSU_APP_PROFILE_VER=3）。
10. builtin 的 `USER_ARG_NULL` 编译 bug 上游已修，旧 sed 补丁删掉，别再加。
11. `/system/bin/su` 缺失：内核只钩 exec 不创建文件；必要时装 `ksu_su_provider.zip` 模块。

## 多 ROM

12. AviumUI/DerpFest 与 LineageOS **同一内核**（e682ed2de56f），但 ramdisk 不同，必须用各自 boot 重打包。
13. DerpFest 官方托管 OneDrive 无匿名直链：把原厂 boot.img 压缩（21.9MB）放进仓库
    `stock_boot/derpfest-16.2/`，CI 免下载（需加 checkout 步骤）。
14. ReSukiSU：默认 Tracepoint 钩子只支持 GKI2；cupid 非 GKI 要用 `KSU_SUSFS`（susfs）或
    `KSU_MANUAL_HOOK`。Kbuild 要 git 完整历史算版本号，必须完整 clone。

## 交互

15. workflow 输入曾过多（8 个参数）；现改为 ROM + 配置预设两个下拉框，preset 自动填充，
    其余参数仅 custom 时手动。旧 GKI `build.yml` 已删除。
